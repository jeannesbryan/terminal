A complete manual for retro terminal CSS/JS components. Terminal UI adds data-attribute helpers, command palette, theme presets, safer JS defaults, and reusable docs/landing modules.

> 02. THEME CUSTOMIZATION

Terminal UI is designed to be customizable. Change the scheme by overriding variables in your custom CSS.

:root {
    --t-green: #ffb000;           /* foreground */
    --t-green-dim: #996900;       /* foreground, dimmed */
    --t-accent-rgb: 255, 176, 0;  /* same colour as R, G, B - see note */
    --bg-base: #110d00;
    --bg-surface: #1f1700;
}

--t-accent-rgb must match --t-green. Every translucent accent wash, including hover glows, tinted panels, dashed borders, the dot grid, focus rings and box shadows, is written as rgba(var(--t-accent-rgb), <alpha>). Override --t-green on its own and the solid foreground changes while roughly fifty washes behind it stay on the old colour, which reads as a colour bleed.

Optional, for full control: --t-white (near-white text, keep a faint cast of the theme) and --t-code-fg (code foreground). Both have sensible green defaults. Legacy comma syntax is required in --t-accent-rgb: rgba(var(--x), 0.05) is supported everywhere, whereas color-mix() and the modern slash syntax are not.

> 33. LAYER SCALE

Every component takes its stacking order from a named token, so adding one never becomes a bidding war over who gets the biggest number. Override a token to move a whole layer at once.

--t-z-base 1   --t-z-raised 2   --t-z-toolbar 100   --t-z-dropdown 1000

--t-z-modal 10000   --t-z-toast 9999   --t-z-palette 99999   --t-z-lightbox 999999

:root { --t-z-modal: 20000; }   /* lifts every modal at once */

.t-my-thing { z-index: var(--t-z-dropdown); }

> 34. NATIVE ACCORDION

Native disclosure, no script
Works with JavaScript disabled. No height ceiling either, so a long panel is not reduced to a scroll box, and closed text is still reachable with the browser's own find in page.

> 35. STEPPER

  1. Build
  2. Verify
  3. Ship

Pure CSS. Numbers come from a counter, the connector from a pseudo element, and the current step from aria-current="step", which is what a screen reader announces anyway. Add class="done" to mark a finished step.

<ol class="t-stepper">
    <li class="done">Build</li>
    <li aria-current="step">Verify</li>
    <li>Ship</li>
</ol>

> 36. CHIPS

Dismissable

.t-badge is a passive label. A chip is a control: it can be selected, and it can be dismissed. Both stay CSS-only by wrapping a hidden checkbox in the label.

<label class="t-chip">
    <input type="checkbox" checked><span>Tor</span>
</label>

<span class="t-chip">Tag
    <button class="t-chip-x" aria-label="Remove"></button>
</span>

> 37. NAVBAR PRIORITY+

BUNKER_OS
[ HOME ] [ SYSTEM ] [ NETWORK ] [ TOR ] [ ONION ] [ LOGS ] [ SETTINGS ] [ ABOUT ]

Shrink the window and the right-most items move into the [ +N ] menu on their own. Widen it again and everything comes back. The original order is kept in JS, so no item is lost.

Order is preserved: items are always taken from the right, because that is the side considered least important.

<nav class="t-navbar t-nav-priority">
    <div class="t-nav-brand">BUNKER_OS</div>
    <div class="t-nav-menu">
        <a href="#">[ HOME ]</a>
        <a href="#">[ SYSTEM ]</a>
        <a href="#">[ NETWORK ]</a>
    </div>
</nav>

<!-- No extra HTML needed. Terminal.navbarPriority() builds the
     [ +N ] button and its list itself on init. -->

Without JavaScript. If the JS fails to load, the .t-nav-priority class still lets the menu scroll horizontally, so every link stays reachable. Only the convenience is lost, not the access.

On narrow screens. Below 768px Priority+ is switched off because the navbar already uses the [ MENU ] button and a collapsing menu. The two mechanisms are never active at the same time.
